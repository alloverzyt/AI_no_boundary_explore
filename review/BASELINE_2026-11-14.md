## 5. 合法打包基线（实测，不改源码）

### 5.1 官方评测器的 ZIP 契约（从 `evaluation_adapters/` 源码核对）

`evaluation_adapters/agent_config.py:31-50` 与 `evaluation_adapters/minecraft_contestant.py:19-57` 规定：

1. ZIP 解压后条目数 ≤ 256、解压总量 ≤ 64 MiB；
2. 拒绝绝对路径、含 `..`、含反斜杠、符号链接、重复条目；
3. **`agent.py` 与 `config.json` 必须在 ZIP 根目录**；
4. `config.json` 必须恰好是 `{"model": {"name","api_url","api_key"}, "agent": {…}}`，字段均为字符串、无 version 字段、≤64 KB、UTF-8 JSON；
5. 加载方式：解压到独立目录 → `sys.path.insert(0, …)` → `os.chdir(…)` → 以 `contestant_agent` 模块名 exec `agent.py` → 实例化 `Agent()` → 有 `configure(config)` 则调用 → 必须有可调用 `act(observation)`。
6. 官方 `pack_agent.py` 会强制把 `config.model.api_key` 清空（密钥运行时注入，不进包）；文件上限 256 个 / 64 MiB；`--extra` 只能引用包目录内文件，冲突报错。

### 5.2 打包 dry-run（临时目录，未污染仓库）

### 6.3 CI 结果验收缺陷（已在本地复现）

把 CI step 3 中的内联 Python 校验代码**原样**抽出（16 行），在临时目录 fixture 上运行：

| 用例 | fixture | CI 校验退出码 | 应有行为 | 判定 |
|---|---|---|---|---|
| A `no_results_at_all` | 有 `practice-output/`，无 `world-*/result.json` | **0（误报通过）** | 应失败 | ❌ 缺陷 |
| B `result_with_empty_episodes` | `world-xxx/result.json` 内容 `{"episodes": [], "summary": {...}}` | **0（误报通过）** | 应失败 | ❌ 缺陷 |
| C `valid_success` | 1 个 episode：`status=completed`、`termination="tutorial_goals"`、`task_success=true` | 0 | 应通过 | ✅ |
| D `failed_objective` | `termination="tutorial_step_limit"`、`task_success=false` | 1（`SystemExit: MineDojo woodcraft objectives were not completed`） | 应失败 | ✅ |

- 根因：校验只对“已 glob 到的 result.json 中的已存在 episodes”做断言；**没有任何“至少 1 个结果文件 / 至少 1 个 episode（且至少 1 个 tutorial 局）”的前置断言**，空集合时循环体不执行 → 空检查视为成功。
- 补充：A 在真实 workflow 里可能先被 `sudo chown practice-output`（目录不存在即非零）挡住，但 B（目录存在、episodes 为空）是真实的误报通过；此外校验也不检查 `status == "completed"`、`summary` 是否存在、result 文件数量，因此结构变化（例如未来 `practice.py` 改名/改路径）也会静默通过。
- 该缺陷已由负责人确认为 task-3 首批修复项；修复必须兼容 §6.2 的真实字段，而不是猜测字段。
