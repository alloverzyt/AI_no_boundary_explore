## 3. 修复

### 3.1 新增 `scripts/validate_practice.py`（离线可测）

规则（严格失败，任一不满足即非 0 退出）：

1. `--output` 目录必须存在；
2. 必须存在 ≥1 个 `world-*/result.json`（防止 A：空结果集误报）；
3. 每个 `result.json` 必须是 JSON 对象，含**非空** `episodes` 列表（防止 B）与 `summary` 对象；
4. 每个 episode 必须是 JSON 对象，且：
   - `status == "completed"`；
   - `termination == "tutorial_goals"`；
   - `metrics` 是对象且 `metrics.task_success is True`（严格布尔，`1`/缺失都拒绝）；
5. 失败时逐条打印 `PRACTICE_VALIDATION_ERROR: …` 到 stderr 并返回 1；
6. 成功时打印 `PRACTICE_SUMMARY` / `PRACTICE_EPISODE`（保留原 CI 日志可读性）与 `PRACTICE_VALIDATION_OK results=N episodes=M`，返回 0。

不联网、不依赖 MineDojo/Docker/密钥、只用标准库，因此可直接在 `unittest` 中测试。

### 3.2 修改 `.github/workflows/minedojo-practice.yml`

| 变化 | 内容 |
|---|---|
| 结果验收 | 原内联 16 行 Python **删除**，改为独立 step：`sudo chown -R … practice-output` + `python3 scripts/validate_practice.py --output practice-output`（失败即 job 失败） |
| 新增 `offline-tests` job（负责人授权补充） | `ubuntu-24.04`，`timeout-minutes: 10`；checkout → `actions/setup-python@v5`（Python 3.11）→ `pip install pillow`（避免 vision 用例被 skip）→ `python -m unittest discover -s tests -v` → `py_compile` 5 个策略模块 + validator |
| 依赖关系 | `woodcraft: needs: offline-tests`，离线测试失败时不再浪费 90 分钟跑 docker |
| 触发路径 | 新增 `"scripts/**"`（验证器改动也会触发 CI） |

docker 运行步骤本身、镜像、`--network none`、`--only woodcraft`、artifact 上传均未改动。
